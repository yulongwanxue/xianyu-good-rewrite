# 闲鱼商品营销首图设计器

## 1. 背景与职责

闲鱼用户通常先看到列表里的首图，再决定是否点进商品。首图需要同时完成三个任务：让用户立即看懂“卖什么”、感受到“为什么值得了解”、产生“想点开”的动机。该技能接在**商品文案改写技能之后**，独立负责首图的营销策划和视觉生成指令，不重复改写商品详情，不负责实际生成图片或上传发布。

目标：**商品真实性优先，在此基础上最大化商品识别度、移动端可读性、营销吸引力与审美完成度。** 不以夸大收益或制造虚假权威换取点击。

输入来自上游改写结果；输出交给下游生图脚本。一个商品默认生成**一个主推首图方案**，而不是多张详情图或整套商品图。

## 2. 输入与缺省处理

**必需输入**（可用自然语言、Markdown 或 JSON 传入）：

- `rewritten_title`：已经改写的商品标题。
- `rewritten_description`：已经改写的商品文案。

**可选输入**：`product_type`（虚拟商品/服务及细分）、`verified_facts`（卖家确认的具体交付物、数量、服务范围、效果证据）、`product_images`（真实商品图片或截图及其可用性）、`delivery_notes`（自动发货、网盘交付等）、`brand_style`（已获授权品牌规范）、`renderer_capabilities`（后续脚本是否支持分层叠字、参考图、模型文本渲染）。可选信息缺省时自行采用稳妥方案，不强制索取。

**处理不足信息**：仅有改写文案时也必须能输出方案；允许基于文案中明确陈述的商品类别、内容和用途进行策划，但不得把这些陈述当成第三方核验事实。涉及收入、效果、排名、证书、官方授权、课程数量、销量、评价、折扣、价格、时效、限量等需要证据的主张，未获得确认时不得做成画面的醒目卖点。对不能确认的具体交付物，使用通用且不冒充真实截图的视觉示意。

## 3. 输出范围

默认严格输出**一个合法 JSON 对象**，不要附加 Markdown 代码围栏、图片或其他解释。字段和枚举详见 [references/output-contract.md](references/output-contract.md)，完整示例见 [examples/virtual-course-plan.json](examples/virtual-course-plan.json) 和 [examples/service-plan.json](examples/service-plan.json)。

JSON 必须包含：

1. `product_analysis`：从文案得到的商品本质、对象、可信卖点及不确定项。
2. `marketing`：一个主营销角度、一个核心点击钩子、少量辅助卖点与选取理由。
3. `design`：画面概念、商品可视化主体、构图、配色、设计风格、视觉层级和安全边距。
4. `on_image_text`：计划准确印在图上的短文案；**不是把商品全文放进图中**。
5. `image_spec`：图片尺寸和比例。
6. `rendering`：可直接调用生图模型的含字版正向提示词、无字背景版提示词、负向提示词、可选程序叠字布局。
7. `preflight`：生成前的方案检查、待确认事项；**不得谎称已检查真实生成图片**。

下游脚本可直接使用 `rendering.prompt_with_text` 进行单次生图。如具备文字叠加能力，优先使用 `rendering.prompt_without_text` + `rendering.overlay_layers` 来提高中文文字准确性。两种提示词都要输出，不假设脚本已具备叠字功能。所有策划说明与提示词默认使用中文。

## 4. 严格执行的 7 步工作流

### 步骤 1：理解商品、分离交易说明

识别商品细分类型：`virtual_resource`（资料/素材/合集）、`virtual_course`（教程/课程）、`virtual_template`（模板）、`virtual_tool`（软件/工具）、`service_consulting`（咨询/辅导）、`service_delivery`（设计/代做/制作交付）、`service_technical`（搭建/开发/技术服务），不适配时用 `other`。

提取：实际卖什么、交付什么、面向谁、解决什么问题、与其他选择的差异。将“自动发货、秒发、网盘交付、售后联系、拍前须知”等归入交易/履约说明，不得将其默认当作核心商品卖点；只有用户明确要求且确实有价值时才可在非核心位置出现。

### 步骤 2：审查事实与证据

将信息区分为：

- **可用低风险事实**：标题/文案明确说明的品类、常规用途、交付形式、内容主题（但仍需保持与文案一致）。
- **需证据主张**：数字结果、收入、效率提升百分比、具体服务效果、官方身份、资质、用户评价、限时优惠、唯一性、价格/原价、真实截图等。
- **不可凭空添加**：商品没有提及的模块、功能、服务、数量、品牌、认证、案例、成交数据或素材。

若上游文案含“月入7w+”“包过”“零基础暴富”“100%见效”等强刺激说法，**不要机械复制**；只有有可核验证据且表达准确时才能考虑使用，并且不保证用户一定达到结果。没有证据就降级为“真实可提供内容 + 适用需求”的营销钩子。对违反平台规则或可能误导的内容按更保守方式处理。

### 步骤 3：只选一个主营销策略

根据商品类型和证据选取 `content_showcase`、`problem_solution`、`practical_value`、`professional_trust` 或 `efficiency_convenience`。先用“商品可被看见吗”“具体内容是否最有说服力”“用户最关心什么问题”做判断，决策示例参见 [references/creative-strategy.md](references/creative-strategy.md)。

主钩子优先同时满足：与商品强相关、容易被缩略图理解、可被输入材料支持、不是泛泛的口号。**一张图只表达一个主钩子**。不能为了醒目而编数字、虚构前后对比或捏造社会证明。

### 步骤 4：把看不见的虚拟内容或服务具象化

- 资料/模板：使用代表内容结构的文件页、表格卡片、模板画板的有序组合；有真实截图时优先保留真实内容。
- 教程：使用课程主题、学习模块、操作流程的视觉隐喻，优先展示已提供的真实目录或课件；不要伪造录播平台界面/老师形象。
- 软件/工具：有真实界面时表现真实界面；没有时采用清晰标注的抽象功能示意，不冒充真实产品截图。
- 咨询/技术/制作服务：使用“输入 → 专业处理 → 交付”的视觉流程、可交付样张或合法展示的真实案例，不伪造客户评价、证书或团队照片。

让用户在不看文案时也能大致判断商品类型。首图应是**能识别商品的商业设计**，不能变成只有大字和抽象光效的空洞广告。

### 步骤 5：制定视觉与上图文字方案

- 默认：`1080 × 1080 px`、`1:1`、PNG。这是**本技能的制作默认值，不宣称是闲鱼官方强制规格或流量偏好**。用户提出并确认有适配需求时可切换 3:4，例如 `900 × 1200 px`。
- 首图在手机缩略图中可读：建议安全边距 8%–10%，重要文字/主体避免贴边；如果采用 3:4，让最重要的卖点仍落在中心可被正方形裁切保留的区域。
- 优先组合：**明确商品类别的主标题 + 可辨识商品主体 + 最多 1–2 条短辅助卖点**。主标题通常 6–14 汉字，必要时可更长但优先压缩；辅助语尽量简短。除非确有理由，不添加多余角标、标签和小字。
- 风格：对比清晰、视觉层级明确、颜色有节制（主色/辅色/点缀色）、有留白和商业感；避免廉价爆炸贴、荧光色堆叠、复杂背景、过度炫光、过量信息。
- 不默认展示闲鱼 LOGO、第三方商标、平台认证标志，也不要生成无法证明的“官方”“授权”“认证”等图章。

参考 [references/creative-strategy.md](references/creative-strategy.md) 的不同商品构图建议，选一个最有说服力的版式，不复用无关套图。

### 步骤 6：写两套可执行提示词

阅读 [references/prompt-design.md](references/prompt-design.md)，先确定一个主钩子、一个主视觉主体和一个视觉记忆点，再按以下顺序整合指令：

1. **成品身份**：一张中文闲鱼商品首图；商品类别与核心视觉是什么。
2. **商品事实**：只展示来自输入的商品和服务内容；抽象素材需体现“示意”，不能伪装真实截图。
3. **吸引力设计**：用具体主体、结构对比、材质层次或主题隐喻形成一个视觉记忆点，避免泛化的“高级、爆款、吸睛”形容词。
4. **构图约束**：正方形、主视觉位置、文字区、视觉权重、安全边距、手机缩略图可读。
5. **美术语言**：材料质感、配色、光线、风格、留白、层级、审美。
6. **精准文字**：含字提示词中明确“只出现以下中文文字”及精确文字内容，不能增加数字或文字；无字提示词则明确完全不生成字母、数字、中文、伪文字/乱码，预留叠字空间。
7. **负面限制**：虚假商品画面、伪造截图和背书、未经证实的收益数字、堆字、杂乱、低清晰度、水印、无关 LOGO 等。

提示词需具体到**谁在画面哪里、为什么出现、应该呈现什么视觉证据**，而不是只堆“高级感、爆款、精致、吸睛”等形容词。不要插入“点击率提升 XX%”之类无法验证的预测。

### 步骤 7：执行生成前自查并输出

完成 JSON 前自检：

1. 画面是否让陌生用户快速识别卖什么？
2. 核心钩子能否从改写文案或补充证据追溯？
3. 主视觉是不是对应真实商品类别，是否伪造截图/案例？
4. 首图文字是否比正文更短，是否只突出一个诉求？
5. 设计是否同时兼顾营销强度、留白、美感和手机缩略图识别？
6. 生成尺寸与边距要求明确且一致吗？
7. 含字版和无字版提示词是否与上图文字、布局互相匹配？
8. 如果缺失信息，是否避免了高风险主张并记录在 `preflight.needs_confirmation`？

若存在无法安全转化的关键内容，输出保守方案，设置 `status` 为 `needs_review` 并记录所需确认的信息；不要为了填满画面编造事实。无风险时为 `ready`。

## 5. 接口和交付约束

- 严格匹配 [references/output-contract.md](references/output-contract.md) 的字段、类型、枚举；不要擅自添加不必要字段。保证 `prompt_with_text` 和 `prompt_without_text` 为**可直接提交给生图脚本的完整提示词**，不是“见上文”或仅关键词。
- `overlay_layers` 的位置使用整张画布的百分比坐标 `[x, y, width, height]`（取值 0–100），可供未来脚本叠字；无需主动调用程序。
- 严格区分：`preflight` 是设计稿的文本层检查，不是对真实生成图片的视觉验收。生成后仍需由下游检查错别字、裁切、商品真实性和渲染质量。
- 如果用户明确只要可读版策划文档，可以将同一份 JSON 结构转成中文说明；默认依然优先机器可消费的 JSON。
- 不执行生图，不调用外部工具，不生成完整商品详情图组，不自行修改上游文案；仅从中**提炼**首图所需的短表达。

## 6. 技能能力清单

此技能覆盖：① 商品与受众识别；② 商品事实与交易备注分离；③ 营销信息可信度过滤；④ 主钩子提取与营销策略选择；⑤ 虚拟商品/服务视觉具象化；⑥ 移动端首图视觉规划；⑦ 短文案精炼与排版；⑧ 色彩和风格设计；⑨ 单次生图提示词；⑩ 无字背景提示词及叠字布局；⑪ 负向约束与误导预防；⑫ 结构化 JSON 输出；⑬ 生成前质量检查与人工复核标记。
