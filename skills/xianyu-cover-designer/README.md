# 闲鱼商品营销首图设计 Skill · 使用说明（v1.0）

**技能名称**：`xianyu-cover-designer`  
**中文名称**：闲鱼商品营销首图设计  
**职责**：只生成**首图设计方案与可执行生图提示词**，不调用生图接口、不真正生成图片、不代替商品文案改写。

## 一、技能背景

在闲鱼列表中，首图承担“吸引注意—迅速理解商品—形成点击兴趣”的前置营销作用。传统的简单裁图、添加宣传字或者直接把整段商品文案贴上去，往往不能同时兼顾商品辨识、可信度和视觉审美。

本技能服务于商品重新发布流程：**上游已有改写后的商品标题和文案；本技能将这些文字转译为商品营销视觉方案；下游生图脚本根据提示词生成实际图片。** 这样既让标题、描述和图片服务于同一商品定位，又保持文案改写和首图生成两项能力解耦。

设计取向：**营销感 + 商品感 + 美感 + 真实性**。优先适配虚拟商品（资料、课程、模板、软件、数字工具）以及服务商品（设计代做、咨询陪跑、技术服务）。

## 二、技能点总览

| 技能点 | 要解决的问题 | 输出/决策 |
|---|---|---|
| 01 商品解析 | 真实卖什么？ | 商品类型、内容/服务范围、受众 |
| 02 信息分层 | 哪些是商品，哪些只是交易说明？ | 商品价值与交付备注分离 |
| 03 事实审查 | 哪些宣传词可以上图？ | 可信事实与需核实的效果/资质声明 |
| 04 营销定位 | 为什么值得点？ | 一个核心利益点或痛点 |
| 05 钩子筛选 | 怎样吸引注意而不误导？ | 强相关、有依据的主钩子 |
| 06 商品具象化 | 虚拟商品/服务怎样“看得见”？ | 主视觉物件和展示方式 |
| 07 版式规划 | 怎样做到有营销感又不拥挤？ | 主体与标题位置、留白和层级 |
| 08 美术设计 | 怎样做到专业、好看、可信？ | 配色、风格、材质与对比 |
| 09 精简上图文字 | 哪些文案值得出现在首图？ | 主标题、短副卖点、可选标签 |
| 10 生成尺寸 | 怎样适合移动端？ | 默认 1:1、1080×1080，安全边距 |
| 11 提示词生产 | 生图脚本具体调用什么？ | 完整含字版 / 无字版 / 负向提示词 |
| 12 脚本对接 | 怎样减少人工改格式？ | 稳定 JSON 契约与叠字坐标 |
| 13 生成前质检 | 怎样避免图文不符？ | 校验结果和待确认事项 |

以上是**设计和提示词生成能力**，并不代表自动审核了实际图片。生图后仍需由下游复核中文文字、裁切和实际商品一致性。

## 三、输入约定

最简输入只需要：

```json
{
  "rewritten_title": "AI办公实战教程｜表格处理与实用流程",
  "rewritten_description": "面向日常办公用户的电子教程，围绕表格整理和常见流程展开，含练习资料……"
}
```

可选补充：`verified_facts`（事实证据）、`product_images`（真实素材）、`product_type`、`delivery_notes`、`brand_style`、`renderer_capabilities`。没有这些内容也可执行，但应采取保守的示意图设计，**不得补造看似真实的素材或夸张承诺**。

## 四、处理流程

1. 读取已改写标题和商品文案；识别真实商品或服务内容、受众与交付类型。
2. 将商品本身与自动发货、网盘交付、拍前须知等交易说明分离。
3. 过滤证据不足的收益、效果、数字、认证、销量、稀缺性等营销主张。
4. 在内容展示、痛点解决、实用价值、专业可信、省时省事五类中选择**一个最适合的主策略**。
5. 设计主视觉；虚拟资源重在内容可视化，服务重在范围、流程与成果类型可视化。
6. 制定 1080×1080 的图文构图方案，精炼一个主标题和 0–2 条可信短卖点。
7. 输出两套完整生图 prompt、一段负向提示词，以及可选文字叠加位置。
8. 输出 JSON，并执行生成前的商品匹配、文案真实性、缩略图与提示词完整性检查。

## 五、输出与下游脚本的关系

默认返回 `schema_version=1.0` 的 JSON 对象，包括：

- `product_analysis`：商品理解
- `marketing`：营销策略与核心钩子
- `design`：首图创意、主视觉、构图、配色
- `on_image_text`：要印在图上的准确短文案
- `image_spec`：宽高、比例、格式
- `rendering`：两套正向 prompt、负向 prompt、叠字区域
- `preflight`：文本层风险与待确认事项

**路线 A：普通生图脚本**直接传入 `rendering.prompt_with_text`，如果生图接口支持，再额外传 `negative_prompt`。

**路线 B：支持程序叠字的脚本**先用 `rendering.prompt_without_text` 生成无字商品底图，再按 `rendering.overlay_layers` 叠加中文。这条路线通常更易保证中文准确，但需要脚本具备叠字能力。

默认首图规格 `1080×1080 / 1:1` 是本技能的制作建议，并非闲鱼公布的流量加权规则。实际入口若需要不同尺寸，再调整配置。

## 六、商品与视觉示例

已包含两组演示数据（非真实商家）：

- `examples/virtual-course-input.json` 和 `examples/virtual-course-plan.json`：AI 办公电子教程。
- `examples/service-input.json` 和 `examples/service-plan.json`：PPT 汇报排版优化服务。

这两组样例用于展示输入和输出格式；**不会自动生成图片**。

## 七、校验和测试

验证输出方案格式：

```bash
python scripts/validate_plan.py examples/virtual-course-plan.json
python scripts/validate_plan.py examples/service-plan.json
```

校验脚本使用 Python 标准库，检查主要字段、枚举值、尺寸比例、颜色、文字同步及叠字区域。它**不能**识别所有虚假宣传，也不能取代对渲染后图片的人工或机器视觉复核。

## 九、能力边界和未来迭代

- **不生成图片**：下游脚本负责模型调用、叠字、图片导出、大小压缩和实际成品质检。
- **不验证商业事实**：若只提供改写文案，文案中高风险承诺应保守处理；需要时要求人工确认。
- **不代替平台规则核验**：官方尺寸/审核规则若更新，以实际入口最新要求为准。
- **不生成整套详情图**：当前默认只策划一张主推首图；后续可以扩展多候选图和 A/B 测试。
- **接口可扩展**：待你确定具体生图脚本/模型后，可将 `rendering` 字段映射到脚本所需参数，保持营销策划部分不变。
