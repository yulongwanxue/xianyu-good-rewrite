# 首图营销策划与设计策略手册

本文件用于执行 `SKILL.md` 的第 2–5 步：从改写文案提炼最合适的营销视觉策略、商品具象化方式、构图和视觉层级。

## 一、目标排序与决策标准

优先级由高到低：

1. **真实对应**：能用输入商品信息解释画面中每个重要卖点/展示对象。
2. **看懂商品**：看到缩略图时能知道是教程、资料、工具、模板还是一种具体服务。
3. **明确利益**：看得出值得点击的理由，但不承诺没有证据的结果。
4. **视觉专业**：不依赖杂乱促销素材，也能有吸引力与可信感。
5. **个性差异**：在上面四项得到保证后再增强形式创意。

避免“更刺激=更好”的简单判断。商品匹配度低的强钩子，往往导致低质量点击与失信。

## 二、选主营销角度（五选一）

| 策略值 | 适用 | 主钩子问题 | 适合的视觉证据 | 避免 |
|---|---|---|---|---|
| `content_showcase` 内容展示 | 资料包、模板、素材、课程 | 具体能得到什么？ | 真实页面/目录/模板缩览及有秩序的堆叠 | 虚构数量、假的资料封面、海量小字 |
| `problem_solution` 痛点解决 | 定制服务、技术服务、工具 | 能帮我处理什么麻烦？ | 任务输入→处理→结果的简化流程 | 假的前后对比、承诺所有情况均成功 |
| `practical_value` 实用价值 | 教程、训练、知识产品、顾问 | 学到/得到什么实用能力？ | 课程主题+真实操作类型/交付形式 | 月入保证、快速致富、绝对结果 |
| `professional_trust` 专业可信 | 高客单服务、咨询、设计、技术项目 | 服务是否清楚且专业？ | 规范交付图、真实案例、清晰工作范围 | 假认证、假人物团队、客户评价 |
| `efficiency_convenience` 省时省事 | 流程工具、表格模板、代做服务 | 减少哪些重复步骤？ | 简明工作流、整洁操作面板示意 | 没有证据的“提效90%”等数字 |

推荐规则：

- 优先让**实际交付物**成为主视觉；若只有抽象服务，才让**服务流程/成果类型**成为主视觉。
- 改写标题中的营销性词语只用来判断用户关注点，不当然是可上图的事实。
- 两个策略均合适时，选可视化证据更充分、移动端更直观的一个。
- 只有标题、描述且无真实图片时，优先设计**概念示意**，不能模仿“真实官方截图”或现成证书。

## 三、适配商品品类

### 1. `virtual_resource` 资料与素材合集

- 推荐：`content_showcase`。
- 主体：1–3 个大尺寸内容页或资料分类卡片，代表资料类型；真实材料优先。
- 主标题结构：`具体主题 + 资料/资源`，例如“自媒体运营资料包”。
- 谨慎：若实际只有文章链接，不能画成厚厚的正式图书/纸质成品；如无内容样张，使用明确的“数字资源示意”设计。

### 2. `virtual_template` 模板

- 推荐：`content_showcase` 或 `efficiency_convenience`。
- 主体：模板局部放大，表格、卡片、演示文稿页面的结构清楚。
- 主标题结构：`适用领域 + 模板`。
- 谨慎：不要伪造模板中具体业绩数据；可用无语义占位卡片或让生成脚本合成真实截图。

### 3. `virtual_course` 教程与课程

- 推荐：`practical_value` 或 `content_showcase`。
- 主体：课程主题图形 + 实操流程/目录/练习页（真实可得优先）。
- 主标题结构：`技能 + 实战教程/课程`。
- 谨慎：不通过金钱、证书、成绩或专业老师照片暗示未提供的效果/资质。

### 4. `virtual_tool` 工具与软件

- 推荐：`problem_solution` 或 `efficiency_convenience`。
- 主体：真实界面（有权使用时）优先；否则抽象的模块化功能图，不能冒充具体软件正式界面。
- 主标题结构：`工具名称/作用 + 工具`。
- 谨慎：没有依据不画具体品牌 LOGO、接口已打通的截图、授权提示、终身会员标志。

### 5. `service_consulting` 咨询、陪跑、培训

- 推荐：`professional_trust` 或 `problem_solution`。
- 主体：具体咨询主题 + 过程与交付的概念图，体现服务范围。
- 主标题结构：`问题领域 + 咨询/辅导服务`。
- 谨慎：不承诺包过、包赚钱、包就业，不生成假专家证书、虚构客户证言。

### 6. `service_delivery` 定制代做、设计制作

- 推荐：`content_showcase` 或 `professional_trust`。
- 主体：明确的可交付成品类型及其美观示例；真实作品优先。
- 主标题结构：`交付类型 + 定制/优化服务`。
- 谨慎：不能把示例设计图冒充真实历史客户案例；未经明确授权不要用知名品牌标识作背书。

### 7. `service_technical` 技术开发、部署搭建

- 推荐：`problem_solution` 或 `professional_trust`。
- 主体：系统模块 / 流程连接的清爽技术视觉，结合服务对象。
- 主标题结构：`技术领域 + 搭建/开发服务`。
- 谨慎：不擅自添加多平台集成/官方认证/系统架构能力。

## 四、首图上图文案：先理解，再压缩

按以下层级写文案：

1. 主标题：**身份词 + 必要价值**。必须保留商品类别词，避免“轻松搞定”“入门必看”这种只表达情绪不表达商品的句子。
2. 辅助点：从真实商品特征抽 0–2 条；尽可能使用短语，而非长句。
3. 小角标：仅用于确有依据的版本、领域或适配对象；不是必须。

示例（仅示意结构，非商品承诺）：

- 教程：`AI 办公实战教程` + `从基础操作到实用流程`。
- 资料：`电商运营资料包` + `按主题分类整理`。
- 工具：`日常表格处理工具` + `常见流程集中管理`。
- 服务：`PPT 设计优化服务` + `统一版式·突出重点`。

不优先使用：不明出处的“100套”“月入7万”“官方认证”“秒杀倒计时”“全网最低”。“零基础可学”只有文案明确覆盖新手、课程内容匹配时才可使用；它仍是目标人群描述，不是保证学成。

## 五、构图选择与产品可视化

### A. 左文右物 / 右文左物

适合课程、工具、设计服务：一侧为 1–2 行强标题，另一侧为较大的电脑页面、资料模块或成品示意。建议主标题对比强、主体占画面显著面积。

### B. 上标题下内容

适合资料合集、模板包：上方主标题，下方 2–3 张层叠内容预览，避免小缩略图密密麻麻。

### C. 中央主体 + 周边微型卖点

适合可具象化工具或服务：中心商品/交付成果清晰，边缘最多两处短文字辅助。

### D. 简化流程式

适合服务与效率工具：明确的“输入—处理—交付”，只允许少量抽象图形和箭头；如果数字/步骤无依据，不随意添加。

### E. 分屏对比式

适合输入材料确有真实的前后对比或可证明流程变化时。若无事实依据，不做夸张“使用前后”真实性对比；可以改为“问题 → 解决思路”的示意流程。

## 六、美术指导

- **高质量不等于豪华堆叠**：建议采用现代编辑式电商风格、产品 UI 展示风格、整洁的教程书封风格等；优先有秩序的空间感与材质。
- **配色不是固定模板**：由商品主题选择沉稳蓝灰、清爽白绿、暖色强调等；常见方案为 2 个主体色 + 1 个点缀色。
- **画面重心明确**：标题一处，主视觉一处，辅助点最多两处。绝不让大背景抢过商品。
- **真实性优先**：只有概念示意时应避免设计成可被误认为真实证据的精密截图。必要时可用“示意图”短标注，或在设计说明中明确展示的是抽象概念。
- **手机缩略图检验**：假设缩到约 180–240px 宽，能否仍读出主标题/识别品类？若不能，删减文字或放大主体。
- **商品感检验**：把主标题遮住后，主视觉仍能大致提示产品类别；否则补强商品展示，而不是加更多宣传语。

## 七、营销吸引力与视觉完成度的平衡

内部自检采用五项各 0–2 分的**策划评估**，不作为点击率预测：

- 真实匹配（0–2）
- 商品辨识（0–2）
- 可信利益点（0–2）
- 缩略图清晰（0–2）
- 版式审美（0–2）

优先把低于 2 的“真实匹配”和“商品辨识”补好，再考虑其他维度。评分只用于改进方案，不能视作实际广告表现数据。
